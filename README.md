## 当前任务

输入一个朝向、位置任意的单个零件三维模型，自动推荐适合打印的姿态，输出能直接用于后续支撑设计和切片的旋转结果。历史数据中的朝向已由用户确认是实际打印并验证可用的姿态，因此可作为正向监督样本。第一版的目标是减少工艺员从任意初始朝向开始反复摆放的时间；支撑评估帮助排序候选姿态，不要求第一版替代 FastLayer 的支撑生成。

```text
历史已打印的零件姿态（可用正样本）
      ↓ 施加随机输入旋转，并同步计算标签
形状相同、朝向任意的输入模型
      ↓ 姿态推荐器
回到历史验证过的打印朝向，或输出少量可行备选
      ↓
FastLayer 复核、设计支撑、切片
```

对每个确认后的历史网格 `V`，施加一个随机旋转 `A` 生成输入 `V' = A V`；若历史网格本身已在构建坐标系中，监督旋转就是 `A⁻¹`。更一般地，历史姿态到构建坐标系的变换若为 `P`，那么从 `V'` 回到该历史打印姿态的变换是 `P A⁻¹`。坐标变换约定需从 PJF 与 FastLayer 核对后固定。先做居中和落平台处理，再输出姿态旋转，避免把无意义的初始平移误当成学习目标。

## 推荐的第一版

先用**历史姿态 + 人工可解释的几何候选搜索**建立基线，再评估是否需要端到端神经网络：

1. 对每个根零件提取自身三角网格，依据父子关系把 `s_` 子网格单独识别为支撑，不把支撑并入输入零件形状。用原软件对照若干工程，检查网格边界、坐标方向和支撑划分。
2. 对历史正样本施加均匀随机三维旋转，生成任意朝向的输入和对应的逆变换标签。这个增强能训练系统应对任意输入朝向，但**不会增加独立零件几何的数量**。
3. 对输入形状生成候选构建方向，先按硬约束过滤，再用构建高度、平台占用、悬垂/支撑需求代理量、孤岛和细长特征排序。限制候选角度或网格分辨率，以便快速响应。
4. 输出推荐姿态、少量备选、旋转矩阵和理由，并显示原历史验证姿态作为基准；将旋转后的网格或矩阵传入 FastLayer，由工艺员复核并完成支撑与切片。

首版的关键评估不是随机增强样本上的训练准确率，而是**新零件族**上的可用性。按零件族或构建项目分组划分验证，防止同一零件的不同旋转版本同时进入训练与测试。测试时对同一零件多次随机旋转，检查推荐是否回到等价的可行姿态；将对称件的等价旋转合并，不能只用普通 Euler 角误差评价。记录工艺员 Top-1/Top-3 接受情况、硬约束违规数和摆放决策时间。

初步识别出约 193 个历史部件对象（另有 11 个 Box 根对象待分类），可用形状数量仍然有限。随机旋转只扩充朝向，不扩充形状，因此建议先用几何评分、最近案例和轻量排序模型；网络可在数据增加后用于候选排序。历史姿态是有效正样本，但未提供“其他姿态不行”或“历史姿态一定最优”的监督，不能把随机生成的其他朝向统统标为负样本。不同材料、关键表面、强度方向和装夹要求也可能使一个形状存在多个同样有效的姿态。

## 支撑和风险在任务中的位置

支撑预测是位姿推荐的评价依据之一，不是当前主要交付。可按工艺设定的悬垂临界角检查外法向与构建方向关系，再结合切片、平台接触和下方承接面估算支撑需求。悬垂阈值、支撑体积和孤岛都是几何代理指标，需要与 FastLayer 实际支撑结果对比。真实失败/变形概率还需要失败、变形等负面结果数据及独立校准，不能由全部成功的历史样本单独推断。

STL 输出在 `outputs/meshes_stl/`，按工程分组：`parts/` 为 193 个主零件候选，`supports/` 为 234 个支撑候选，`review/` 为 11 个待确认的 Box 对象。`manifest.json` 记录原始工程名、零件名、对象 ID、父子关系、原始配置和每个 STL 的相对路径。角色由命名及父子关系推断，仍需抽查。导出保留全部原始三角面和顶点坐标，不居中、不缩放，也不应用对象或父对象变换；坐标与单位仍需对照 FastLayer 确认，不能直接把这些文件当作已复原的整板布局。STL 不保存单位、材料和共享顶点索引；需要原始索引时使用上述 NPZ 导出。

当前点云导出在 `outputs/pointclouds/`：每个根零件对应一个 `.npz`，含均匀表面采样点、采样面法向和原网格哈希；`features.csv` 含包围盒尺寸、表面积、PCA 特征值比例和半径统计，`manifest.json` 保存零件/工程对应关系、材料与历史姿态来源。点云与数值特征使用原始模型坐标，不擅自换算单位。法向保留原网格三角面绕序，尚未证明全部朝外。

点云和 PCA 描述符可用于 PointNet 类模型、检索或排序候选姿态；训练位姿时要中心化以消除任意平移，并同步旋转几何点、法向和方向标签。当前方向网络将输入等比例归一化到单位球，原始尺度仍保留在网格和导出元数据中。单靠无朝向的旋转不变特征不能恢复目标朝向。审计及点云脚本只做解析、采样和特征导出；训练与姿态推理由后述脚本完成，均不会更改源工程。

## PTv3 预训练特征与方向 Head

当前实验使用 [Utonia Tiny](https://github.com/Pointcept/Utonia)（约 932.6 万参数）的 PTv3 编码器，冻结编码器，对所有层级分别做 mean/max pooling，接 `972 → 256 → 64 → 3` 的方向 Head。XYZ 以点云中心居中、按最大半径等比例归一化；PTv3 接收 9 个通道：XYZ、零颜色和三维法向。第一轮训练将法向置零；法向保存在点云文件中，后续消融可启用。默认使用 2048 个采样点、0.02 归一化网格、128 点注意力窗口，关闭 FlashAttention，使用 PyTorch 注意力后端。原始 STL 的尺寸不会随网络输入归一化改变。

本机已使用 WSL2 Ubuntu 24.04、Python 3.12、PyTorch 2.8.0+cu128 在 RTX 5070 Laptop 8 GB 上验证 CUDA。Windows 默认 Python 3.14 环境继续用于数据解析，训练环境独立放在 WSL 的 `~/envs/fastlayer-ptv3`。需要联网下载几 GB 的 PyTorch/CUDA 依赖；网络代理如有需要，请在当前 WSL shell 中设置 `HTTP_PROXY` / `HTTPS_PROXY`。

在 WSL 中初始化环境和下载权重：

```bash
cd /mnt/d/proj/pos_set
bash tools/setup_training.sh
```

权重固定到 Hugging Face `Pointcept/Utonia` 的 `9457f025e36c7001ee962a542f0d27a5b600e1e7` 版本，文件 `utonia_tiny.pth` 为 37,390,848 字节，SHA256 为 `e49a1944403d4ec3df459537fb7d5b132326736d0ebdb7c5a74868f3fa50d137`。官方代码固定到 `5fce241d3fd943bdef2db14fdd41fff8b090d98e`。权重采用 CC-BY-NC-4.0，商业使用需另行确认许可。第三方代码、权重、训练缓存和运行结果均由 `.gitignore` 排除。

训练和推理命令（WSL）：

```bash
~/envs/fastlayer-ptv3/bin/python -u tools/train_orientation.py \
  --train-rotations 16 --validation-rotations 8 --epochs 120 --points 2048

~/envs/fastlayer-ptv3/bin/python tools/predict_orientation.py \
  /mnt/d/path/to/single_part.stl --clearance 0
```

训练先按工程分组；若不同工程共享名称中的九位零件编号，则先合并工程组。选择接近 20 个对象的完整组作验证，其余训练；当前数据划分为 173/20。旋转增强发生在划分之后，每个训练对象固定 16 个随机旋转、验证对象固定 8 个旋转。此划分尚未经过几何去重和人工零件族复核，不能据此认定没有相似形状泄漏。验证集用于选择最佳 epoch，不是独立测试集。

采用列向量约定：历史点 `p` 随机旋转后为 `R p`，方向标签是 `R [0,0,1]ᵀ`；损失为 `mean(1 - dot(predicted_up, target_up))`。这是建立在原始历史网格 +Z 为打印向上的待核实约定上的试验。冻结编码器的随机朝向特征缓存后，使用 AdamW 训练 Head，特征均值和标准差仅由训练集计算。保存目录 `runs/utonia_tiny_direction/` 含 `split.json`、`config.json`、`features.npz`、`best_head.pt`、`metrics.json`、`validation_predictions.npz`。不同特征提取配置不会混用缓存。

推理脚本输入单个无支撑 STL，预测输入坐标系中的打印向上方向，再计算将其对齐 +Z 的最小角度旋转，中心放到 XY 原点，并把最低点放在 `--clearance` 指定的原始单位高度。输出 `outputs/predicted_pose/*_oriented.stl` 与 `*_pose.json`；JSON 保存旋转矩阵、平移向量和完整 4×4 变换。只预测方向，因此未学习绕打印 Z 轴的转角。当前角度指标针对单一历史方向，未处理对称等价摆法，也不等于可打印率；最终摆法仍需 FastLayer 与工艺员复核。

### 法向与随机朝向消融

点云 `.npz` 中已有与表面采样点对应的三角面法向。启用 `--use-normals` 后，位置、法向与方向监督目标使用同一旋转，颜色通道仍为零。消融脚本在相同工程划分、随机种子、8 个固定验证朝向/零件、Head 初始化和训练设置下，对比 4 种配置：16 或 64 个训练朝向，有法向或法向置零：

```bash
bash tools/run_orientation_ablation.sh
```

每个零件的 64 个随机旋转下的点采样、法向、方向标签及验证输入在两种朝向数量对照中保持一致。16 朝向方案仅取缓存中每个零件最前 16 项训练 Head；64 朝向方案使用全部。不同法向设置使用分开的缓存。每组模型、配置、指标和曲线记录于 `runs/utonia_tiny_direction_ablation/`。

各组均训练 120 epoch、batch size 256。一个训练样本是“一个零件的一种朝向”；Head 每轮将训练集中的零件-朝向实例全局打乱后按批次更新，因此一个 batch 可含多个零件、多个朝向，并非同一零件的正反朝向配对。16 朝向组每轮约 11 次更新，64 朝向组约 44 次更新，所以结果同时反映角度覆盖和总训练量，不能完全分离两者。四组使用统一的新随机流，本次重新训练的 16 朝向/零法向组作为基线，不能直接与首轮 80.205° 混比。训练完成后运行以下命令校验配对标签、生成结果表与训练曲线：

```bash
~/envs/fastlayer-ptv3/bin/python tools/summarize_orientation_ablation.py
```

网格只读审计命令为 `python tools/audit_training_meshes.py`（需要训练环境中的 trimesh）。当前精确合并重复顶点后，168/193 个网格通过闭合检查，193 个均为一致绕序，13 个包含退化三角面，采样点法向全部与来源面匹配。检查不修改数据，也未做自相交检查，不能把闭合和正的整体有符号体积等同于每个壳层法向均物理朝外。

### 特征提取加速

默认以 `--encoder-batch-size 32` 批量 GPU 推理，`--workers 1` 在后台线程提前准备下一块，主线程同时运行 GPU。所有点云只读取一次；每 512 个朝向保存一个独立特征分块，重启时从已验证的配置对应分块继续。完整特征缓存可在 16/64 朝向的 Head 之间复用，命中缓存时不再构建 GPU 编码器。Head 使用 fused AdamW，并在每轮汇总 loss 后才做 CPU 同步。

Utonia 原始非 Flash 注意力会根据批中最少点数缩小窗口。`tools/batched_attention.py` 在冻结编码器的 eval 模式下使用带掩码的批量 SDPA，为每个样本保留原来的窗口和尾部重复点；小样本填充只用于张量对齐，填充位置不参与注意力。序列化深度不同的样本仍分组处理，且关闭所有层级的随机排序，以保证与单样本推理可比。该后端仅支持冻结、无 RPE 的当前模型；不用于编码器微调。

`tools/benchmark_feature_extraction.py --samples 256` 覆盖全部 193 个零件，比较官方逐样本前向与加速前向。当前版本实测纯 GPU 编码从 20.13 秒降到 0.81 秒（约 24.9 倍），最大特征绝对差约 4.8e-6；batch32 的 PyTorch 峰值显存约 181 MiB。包含预处理与保存的实际提取加速以每轮 `extraction_timing.json` 为准。1/4/8 个预处理线程均已测速，本机当前 NumPy 操作使用 1 个后台线程更快，支持按机器调整。未减少点数、方向数、训练轮数，也未启用混合精度。

~/envs/fastlayer-ptv3/bin/python tools/summarize_pointnet_real_parts.py

# 当前预览沿用 PTv3 法向+64 朝向的预测，每件取第一个固定验证朝向
