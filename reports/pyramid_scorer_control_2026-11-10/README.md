# 金字塔数据集上的打分器对照实验（2026-11-10）

状态：完成。**结论：同样的打分器形式，在“目标唯一且形状简单”时能把验证误差压到 0.46°；
所以在真实零件上的 47–54° 不是形式或容量的错，而是标签本身的问题。**

## 目的

前面的真实零件实验里，打分器能把人工摆向排进前 1.4%，但 top-1 只有 47–54°，无法定位。
需要回答一个控制问题：**是打分这个形式学不到精度，还是真实零件的目标不可学？**

公开金字塔数据集（`datasets/public_pbflbm/pyramids_10000.zip`，PBFLBM，官方划分
8100/900/1000，单个参考构建轴）正好是“目标唯一、形状参数化”的控制组。

## 配置

| 项 | 值 |
|---|---|
| 数据 | 复用 `runs/public_pyramids_axis_v2/pointcloud_cache.npz`（8100 训练 / 900 验证，每件 2048 点） |
| 输入 | 仅 XYZ（公开缓存无法向），去中心/尺度已由缓存完成 |
| 物理特征 | 无（金字塔没有支撑/平台标注） |
| 候选/样本 | 正样本 1 + 近距离负 2（5–15°）+ 中距负 3（20–70°）+ 随机负 2 |
| 损失 | 8 路 listwise softmax，温度 0.05 |
| 模型 | 与真实零件实验相同的打分器，3 输入通道，115,585 参数 |
| 优化 | AdamW 2e-3，20 轮，batch 64 |
| 评估 | 512 候选 + 多步爬山（8°→4°→2°→1°），100 个验证样本，yaw 平均 |

## 结果

| 轮 | 训练 loss | 验证平均 | 中位 | P90 | ≤3° |
|---:|---:|---:|---:|---:|---:|
| 1 | 0.1920 | 2.278° | 2.341° | 3.237° | 75% |
| 4 | 0.0048 | 1.522° | 1.442° | 2.326° | 97% |
| 8 | 0.0022 | 1.094° | 1.090° | 1.648° | 100% |
| 12 | 0.0002 | 1.351° | 1.292° | 1.925° | 100% |
| 16 | 0.0002 | 0.795° | 0.801° | 1.301° | 100% |
| 20 | 0.0004 | **0.463°** | **0.430°** | **0.795°** | **100%** |

与既有结果对比（同一数据集，不同实现与预算）：

| 方法 | 验证平均 | 测试平均 |
|---|---:|---:|
| PointNet 从头训练（本项目，`public_pyramids_model_comparison`） | 0.71° | 0.71° |
| PointNet 式回归（本项目早期复现，`public_pyramids_axis_v2`） | 1.32° | 1.33° |
| PTv3 从头 / 预训练（同项目） | 1.96° / 2.10° | 2.00° / 2.19° |
| **本实验：打分器 + 局部细化** | **0.463°** | 未测 |

## 解读

1. **形式不是瓶颈**：打分 + 排序 + 局部细化在同一类几何上可以达到 0.46°，比单方向回归的
   0.71°/1.33° 不差；而这两个数字来自同一位姿输出空间的两种完全不同的训练方式。
2. **真实零件的瓶颈是标签**：同一套打分器、同样的候选与损失，换到真实零件的多解标签上，
   top-1 是 47–54°，人工排名却能进前 1.4%。也就是说模型学到的是“哪里大致对”，
   而不是“师傅选的那一个”。
3. **这个对照也说明“简单件能摆对”已经成立**：参数化金字塔在 1° 量级；
   若要在产品上先覆盖简单件，直接用“规则 + 细化”或这个打分器都可行。

## 注意

- 本实验没有跑测试集；0.463° 是 100 个验证样本上的数字，且用了爬山细化（回归基线没有搜索步骤），
  两者不是严格同口径，不能直接宣称“优于 PointNet”。
- 金字塔只有单一家族、单一参考轴；它不检验“多个可接受姿态”（正方体/圆柱的任一面朝下），
  也不检验支撑规则、真实拓扑多样性。
- 该数据集的目标本身由数据发布方给出，未独立核验其工艺最优性。
